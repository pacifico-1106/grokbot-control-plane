### 1.1 顧客に出してよい事実（LP・カタログ正本）

## 2. ターゲットセグメント

初期はエンプラより日本の中小。決裁が短く、デモがその場で効く（営業イネーブルの優先順位に合わせる）。

### 優先1: 日本の中小企業の社長・経営者

- **刺さる言葉:** 承認なしでは危ないことはしない／記録が残る。禁止すると現場が隠れる。  
- **入口プラン:** Intern（日報・議事録・FAQ 一次案・空き確認）。月5万円・1業務から、と LP どおりに話す。  
- **上げる条件:** 問い合わせ一次返信・見積整理・商談日程・フォロー抜け漏れ → Proper。  
- **使わない言葉:** 無料で試せる、フルオートで全部任せる、LINE ですぐ承認。

### 優先2: 実務リーダー（営業・事務）

- マンガ「プロパー」編（`/lp/ai-employee/manga/proper`）を先に渡す。  
- 体験は Slack Connect のハンズオン（後述）。承認は自社側で見せる。

### 優先3: 情シス兼務がいる小規模組織

- 社員証・職務ごとの権限・監査、を先に話す。  
- セットアップはハンズオン（プレイブックの安藤＋スタッフ分担）。セルフ構築を前提にしない。

### 優先4: AI Concier（電話入口）利用者・検討者 — フォロー役としての Staffpass

リポジトリ上の位置づけ:

- `docs/copy.md`: Jurin（AIコンシェル／電話入口）は **Coming soon。統合済みではない**。  
- `docs/staffpass-situation-policy-catalog.md` A4: AI Concier は「ルール設計の参考＆将来連携候補」。電話 surface は予約。  
- Proper の業務例に「問い合わせ一次返信」「フォローアップのリマインド」「商談日程候補」がある。

**話し方（連携済みとは言わない）:**

1. 電話の一次受けは先方の入口（AI Concier 等）のまま。  
2. Staffpass は**着信のあと**に動く受け側——一次返信下書き、日程候補、フォロー抜け漏れ、承認してから外に出す。  
3. 今つながる口は Slack と会社メール（メールの実送信は未実装なので、体験では Slack を主にする）。  
4. 電話連携そのものを「今四半期で入れる」とは言わない。年内の口の拡張は LINE / LINE WORKS が先。

対象の探し方（目標でありリスト件数の実績ではない）:

- 電話AI・コンシェルを既に案内している中小（士業、不動産、クリニック、訪問サービス等）  
- 「電話は取れるが、その後のメール・Slack が止まる」が痛み

## 3. チャネル方針

### 3.1 LP パターンA `/lp/ai-employee` — 公開着地

- 検索・X・セミナーの正本。サービス名は「Staffpass」／ヒーローは「AI社員 by Staffpass」。  
- キャンペーン帯あり。セットアップは12月以降、と聞かれたら LP どおり答える。  
- CTA: 「相談する」→ `/lp/ai-employee/consult`。「漫画でイメージする」→ `/lp/ai-employee/manga`。  
- チャット（フラグ ON 時）は購入・契約を確定しない。人への引き渡しは handoff 確認ページ経由。  
- **担当:** 流入監視・フォーム一次対応は安藤。商談化は八坂。

### 3.2 LP パターンB `/lp/ai-employee-corp` — 紹介専用

- 検索に出さない（noindex、sitemap 外、`X-Robots-Tag`）。**公開広告の着地に使わない。**  
- サービス名は「Staffpass（AIエージェントの社員証）」。キャンペーン帯なし。ヒーロー直下に相談 CTA。  
- `?ref=partner_01` 形式のみ Cookie 保存。紹介元は通知メールに「紹介元(ref)」として残る。  
- マンガ・相談・Checkout には `from=ai-employee-corp` が付く。  
- **担当:** 紹介先リストと個別送付は安藤。紹介元への一言は八坂が必要なときだけ。

送付文の型（目標テンプレ。実績の開封率は不明）:

> 知人向けのページです（検索には出ていません）。漫画 → 料金 → 相談、の順で見てください。無料トライアルは無く、Slack Connect でハンズオンします。商談は八坂が担当します。

### 3.3 マンガページ `/lp/ai-employee/manga`

問い合わせ返信の**必須リンク**。プラン別に渡す。

| 相手の痛み | 渡す話 | 次 |
|------------|--------|----|
| 日報・議事録・社内案内 | intern | Intern の相談 or Checkout |
| 問い合わせ・営業フォロー | proper | Proper。AI Concier 利用者もここ |
| 経営サマリー・開発保守 | executive | Executive／カスタマイズは相談のみ |

各話の CTA は「相談する」。無料サインアップへ飛ばさない。

### 3.4 フォーム営業キット（リポ既存物の組み合わせ）

キットの中身（新規制作しない。既存を束ねる）:

1. マンガ該当話の URL  
2. 相談フォーム（プラン prefill 可: `?plan=intern|proper|executive|custom`）  
3. `docs/sales-pack/staffpass-proposal.pdf`（金額は LP より古い場合あり。**金額は LP を正**と口頭で補う）  
4. セキュリティ FAQ から「Bot分け≠安全」「承認まで実行しない」の2点だけ抜粋

運用:

- 宛先は社長または実務リーダー。一斉大量送信はしない（2週間の接点目標に収める）。  
- 送付後の返信窓口は安藤。商談希望が出たら八坂の枠へ。  
- **担当:** リスト作成・送付・追跡は安藤。文面最終確認は八坂（初週1回）。

### 3.5 Slack Connect ハンズオン（無料トライアルの代替）

**無料トライアルは無い。** 体験は Slack Connect のハンズオンのみ。

やり方:

1. 安藤が先方 Slack へ Connect 招待（共有チャネルはデモ会話用）。  
2. 八坂が 30–45 分で、社員証・承認で止まる・監査が残る、の3点を見せる（イネーブル §6）。  
3. 承認カードは**自社ワークスペースの DM／管理画面**に出す。Connect 共有チャネルには出さない（P0）。  
4. メール実送信デモはしない（`mail.send` スタブ）。代わりに Slack 投稿またはカレンダー候補。  
5. 終了時: マンガ URL、料金（税別・初期費用と月額の違い）、12月以降セットアップ、相談フォーム。

**担当:** 招待・日程調整は安藤。実演とクロージングは八坂。Connect 診断が必要なら木村。

## 4. 問い合わせ返信ルール（全チャネル共通）

安藤が一次返信する。例外なく次を守る。

1. **マンガを送る。** 必ず `/lp/ai-employee/manga`（必要なら intern/proper/executive）。`/lp/manga` は送らない。  
2. **無料トライアルは無い、と言う。** `/signup` の「無料で試す」に誘導しない。代わりに Slack Connect ハンズオンを提案する。  
3. **商談は八坂。** 安藤は日程候補を取り、カレンダー確定は八坂。安藤がクロージング商談を持たない。  
4. **料金は税別・LP どおり。** 初期費用と月額を分けて話す。月額の自動課金は「今は契約後に人手」と正直に。  
5. **開始時期は12月以降**（LP A キャンペーンに合わせる）。前倒し確約をしない。  
6. **できないことを先に言う。** メール実送信未実装、LINE 承認は対応予定、契約自動化なし。  
7. **相談フォーム経由は1営業日以内に安藤から連絡**（プレイブックの SLA）。X・紹介・フォーム営業の返信も同日中を目標。  
8. 即決 Checkout が来たら安藤が通知を受け、セットアップはプレイブックどおり。月額契約は人手。商談が残っていれば八坂が同席。

一次返信の骨格（目標テンプレ）:

> 漫画でイメージ → 料金は LP の税別 → 無料トライアルは無く Slack Connect で体験 → 商談は八坂 → セットアップは12月以降 → 相談・即決は既存フォーム／Checkout。

## 7. 開発ボトルネック（営業が待たされる点）

本期間の新規機能コミットを営業目標に含めない。決裁が出たものだけ木村／森が手を付ける。

### 7.1 `mail.send` はまだ本当に送らない（PR #366 ＋ `gmail.send`）

- 現状: 承認後も `fulfillMailSend` は記録のみ。`delivery: "stub"`。ライブ送信経路が無い。  
- Gmail API は `calendar.freebusy` のみ。`gmail.send` スコープもクライアントも無い。  
- AgentMail は予約（501）。Resend は制御面の通知専用で、AI社員の `mail.send` には使わない。  
- #366 は添付と Gmail スレッド情報を metadata に載せるところまで。本番配信は「今日システムから出ない」。  
- **決裁後の実装規模（依頼どおりの見込み）:** `gmail.send` 経路で **1–2日**。決裁は八坂。着手は木村／森。  
- 営業: メール実送信をデモしない。体験は Slack。顧客の「問い合わせ返信を自動送信」は、承認＋下書きまで、と話す。

### 7.2 契約・支払い自動化は未構築

プレイブック Out of Scope のまま:

- 月額サブスク自動開始（Checkout → subscription）  
- Webhook での自動 org 作成  
- hire 完全自動化  
- カスタムプランの自動見積  

外部契約カード登録は設計ロックのみ（実装・本番有効化なし）。紹介報酬の自動送金も無し。

営業: 初期費用 Checkout は使ってよい（Price ID が環境にある場合）。月額・契約書・組織作成は人手（安藤）。「申し込んだらすぐ社員が動き出す」とは言わない。

### 7.3 LINE / LINE WORKS は年内ターゲット

- LP・料金表の顧客向け表記は **「対応予定」**。これを「今できる」に言い換えない。  
- リポジトリには LINE の会話送信・1:1 wake など実装が進んでいるが、**営業コピーの正は LP**。  
- LINE WORKS は設計コメント（H1）レベル。顧客約束に使わない。  
- 依頼どおり、LINE と LINE WORKS は**年内**をターゲットとする。本2週間のリード獲得条件にしない。  
- 担当: 実装は木村／森。顧客向け文言の変更は LP を直すまで禁止（安藤／八坂）。

### 7.4 緊急停止の二人解除テストが未実施

- テナントの緊急停止（開始）と、解除は Web・再ログイン直後・申請者以外、は実装されている。  
- 運営コンソールからの停止（ops hold）の解除は S4（運営2人）。S3 UI には解除が無い。  
- **二人解除のリリース試験は未実施。** 本期間中に木村／森が試験手順を1回回す（目標）。合格するまで、営業は「緊急停止は今すぐ止められる。解除は別の人がダッシュボードから」と LP／FAQ の範囲で話す。運営2人解除の運用確立を顧客約束にしない。
