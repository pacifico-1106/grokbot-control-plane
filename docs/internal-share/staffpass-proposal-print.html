Staffpass ご提案書

説明できる AI 社員 — for Grok Bot
対象：中小企業の社長・経営者の方へ
作成日：2026年8月23日
ブランド：Staffpass

1. はじめに — ひとことで

現場は AI を使いたい。社長は事故の説明責任を負っている。
禁止すると現場は隠れて使い、便利さだけ先に付けると「動くが説明できない AI」になります。

Staffpass は、Grok Bot の上に AI社員の社員証・社長承認・仕事の記録 を載せる製品です。
手足（実行環境）は共有でも、会社の言葉で境界を説明できるようにします。

キャッチコピー： AIを入れるな。AI社員を雇え。
顧客に渡す一言： Grok Bot は優秀な手足です。Staffpass は、その手足に社員証と承認印を付ける製品です。

2. 課題 — いま社長のところで起きていること

2.1 現場と経営のズレ

現場 経営・社長
ChatGPT やエージェントで仕事を速くしたい 何を外に出したか分からないと不安
便利ならすぐ試す 事故が起きたときの説明責任は自分
禁止されると隠れて使う 「使わせたいが止めざるを得ない」

2.2 やりがちな失敗

  1. 全面禁止 → シャドー利用が増え、かえって見えなくなる
  2. 監視だけ強化 → 現場が折れ、導入が止まる
  3. 決済や連携だけ先に付ける → 動くが、職務・承認・証跡がなく説明できない

2.3 見落としがちな技術的事実：共有PC

Grok Bot では、実行用コンピュータがユーザー配下で共有されることが一般的です。

  • 分かれるもの： 画面（デスクトップ）はエージェントごと
  • 共有されうるもの： ファイル、入れたツール、ブラウザのログイン状態

したがって、OS の権限だけでは「営業Bot」と「経理Bot」の職務分離になりません。
Bot を増やしても、手足は同じ箱です。情シスや社長が直感的に抱く不安（「同じパソコンなら分離にならない」）は、事実として正しい部分があります。

提案の核心： 危険なのは「共有であること」自体より、境界が無いことです。境界の主戦場を OS から、社員証・承認・監査へ移します。

3. Staffpass とは何か

3.1 製品の位置づけ

役割 担い手
手足（チャット・ツール実行） Grok Bot
就業規則と日報（権限・承認・記録） Staffpass（制御面）

Staffpass は LLM そのものではありません。Grok Bot の外側に載せる 制御面（Control Plane） です。

3.2 四つの層

層 内容 社長にとっての意味
社員証 職務・目的（purpose）・スコープ・期限。失効できる 「この子はここまで」を決められる
ゲート すべてのツール実行を必ず通過。不一致は fail-closed（止める） 権限外は動かない、が製品として保証に近い
承認 危険操作は人間が「要対応」で許可してから実行 社長（または代理人）がボタンを押すまで進まない
監査 プロンプト全文ではなく、誰が・何目的で・何をしたかの構造化証跡 あとから説明できる。チャット履歴頼みから卒業

3.3 導入モード

モード 説明
Managed 弊社が Grok Bot のセットアップと制御面への接続を巻き取る（情シス不在の中小向け本命）
BYO すでにある Grok Bot にゲート／監査だけ接続

4. 解決の進め方 — 4ステップ

  1. 認める — 手足の環境は共有。隠さず、商談の最初に事実を共有する
  2. 雇う — AI を「入れたソフト」ではなく AI社員 として採用する
  3. 境界を張る — 社員証・承認・監査で、営業と経理など職務ごとにできること・ログ・承認を分ける
  4. 巻き取る — 難しい接続は Managed。社長は方針と承認に集中する

トーンの原則： 禁止するな。説明できるレールを敷け。

5. デモで必ず見せる3点

商談・体験会では、次の3点だけは必ず画面で見せます（NG：自動で何でも買ってしまうデモ）。

  1. AI社員の権限 — 「この子はここまで」が見える（社員証・職務・スコープ）
  2. 承認待ちで止まる — 社長がボタンを押すまで危険操作が進まない
  3. 監査タイムライン — 1業務を時系列で追い、「誰が・何目的で・何をしたか」を説明できる

（発展）承認付きの実取引デモ（例：eSIM 1件）は、信頼の証明として有効です。未完成の機能は約束しません。

6. Before / After（Staffpass が入ると何が変わるか）

よくある不安 Bot だけ Bot + Staffpass
誰の手か分からない 共有環境の能力がそのまま見える AI社員ごとに権限とログ
勝手に外部送信・課金 止めにくい 承認ゲート・fail-closed
事故の説明 チャット履歴と人の記憶 構造化監査・コストボード
セットアップ 顧客が全部負担 Managed で巻き取り可
セッション切断と紐づけ 不安・リセット感 永続バインディング。切れても「要再連携」と明示し、黙って消さない

一文： 同じコンピュータでも、営業Botと経理Botでできること・残るログ・必要な承認が違う。

7. よくある質問（FAQ）

Q1. データは学習に使われるのか？

Staffpass 制御面は、業務の構造化記録が中心です。プロンプト全文や思考過程（CoT）を溜めない設計方針です。
Grok Bot／モデル側の学習可否は、Bot 側の契約・プラン事項です。営業時は公式ヘルプ／契約で最終確認し、「学習は Bot 契約、権限と記録は Staffpass」とセットで説明します。

Q2. うちに情シスがいない

だから Managed があります。難しい接続はこちらでやります。社長・実務リーダーは「承認」と「方針」に集中できます。

Q3. すでに ChatGPT を使っている

併用でも構いません。社外に出る操作や、社内の「公式 AI社員」だけを Staffpass 配下に置く入口でも始められます。

Q4. 共有PCのままでセキュリティは大丈夫か？

共有であること自体より、境界が無いことが問題です。Staffpass は Gateway 経由以外は通さない／紐づけ不明は止める／監査に残す、を会社の説明にします。将来マシンが分かれても制御面は残り、防御が二重になるだけです。

Q5. 紐づけはセッションが切れたら消えるのか？

消しません。ブラウザセッションと社員証バインディングは別です。切れても「要再連携」と明示し、黙ってリセットしません。

Q6. 秘匿情報をマスキングしてから LLM に渡せるか？

技術的には可能ですが、初版の本丸は社員証・承認・監査・紐づけです。マスキング（DLP）は隣接モジュール／拡張として誠実に話します。100% 検出は約束しません。

Q7. Grok Bot とは別料金か？

制御面と Bot 利用は役割が違います。Bundled／分離はご提案時に整理します（金額は別紙）。

Q8. 銀行振込は可能か？

Stripe 経由でカードと振込を取りまとめる方針です。

Q9. 本番はいつか？

トライアルと骨格は進行中です。過大な約束はしません。社員証・承認・請求の接続がマイルストーンです。
