# Staffpass が入ることでセキュリティ説明がどう変わるか

**読者:** 営業・CS・導入担当  
**目的:** 「Grok Bot 単体」と「Bot + Staffpass」の差分を一枚で話す

---

## 1. ビフォー（Bot のみ）

- 現場は便利にチャットできる  
- 会社は「何を許可したか」を製品として持てない  
- 共有実行環境の能力が、実質エージェントに見える  
- インシデント後はチャットログと人の記憶に頼る  

## 2. アフター（Bot + Staffpass）

- 現場のチャットは引き続き Grok Bot  
- 会社は AI社員（器）を採用し、実行体と**永続紐づけ**  
- 危険な手は承認なしでは動かない  
- 活動・コスト・アクションを社員別に追える（経営ダッシュボード）  
- 切れても黙って消えない（要再連携）  

## 3. 顧客に渡す一言

> Grok Bot は優秀な手足です。Staffpass は、その手足に社員証と承認印を付ける製品です。共有のパソコンでも、会社の言葉で境界を説明できます。

## 4. やると約束してよいこと／だめなこと

**よい:** 権限・承認・監査・紐づけの持続・コスト可視化（推計→後に突合）  
**だめ（過大）:** LLM 学習の絶対停止、海外転送のゼロ、マスキング100%、OSレベルの完全分離
