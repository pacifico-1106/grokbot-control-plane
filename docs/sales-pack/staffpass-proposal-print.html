Staffpass 提案資料（印刷・PDF用）

サブタイトル: AI社員証と承認で、Grok Botを会社に入れる

対象: 中小・零細の経営者／決裁者

版: 2026-08-23 ドラフト（社内ブラッシュアップ用）

1. 要約（1分）

現場は生成AIやエージェントを使いたいが、経営は「何を外に出したか分からない」「共有の実行環境で職務が分けられない」と不安です。禁止すると現場は隠れます。

Staffpass は、Grok Bot 上の実行体に AI社員（社員証）・承認・監査・コスト可視化 を載せる制御面です。日常のチャットは Grok Bot、会社としての守りと見える化は Staffpass。

2. 課題

1. 便利だが説明できない

2. 禁止するとシャドー利用

3. 実行環境の共有により、OSだけでは職務分離が困難

4. セットアップと運用が中小には重い

3. 提案内容

3.1 役割分担

  • Grok Bot: 日常業務のチャット・実行
  • Staffpass: AI社員の採用、権限、危険操作の承認、監査、活動／コスト、連携の永続管理

3.2 中核機能

  • 社員証（目的・スコープ・承認ポリシー）
  • 永続バインディング（要再連携、黙って消さない）
  • 承認キュー
  • 監査・社員別アクションログ
  • 活動／コストボード（日次・週次・月次）
  • Managed または BYO

3.3 セキュリティ説明

共有PCは認め、境界を社員証側へ。学習オプトアウトは Bot 契約側。マスキング往復は拡張モジュール候補。

4. 導入効果

  • 「承認なしでは危ないことはしない」と説明できる
  • 社員別に行動とコストを追える
  • 禁止ではなく採用できる
  • Managed で導入負荷を下げられる
