# Staffpass
## AIを入れるな。AI社員を雇え。

中小企業の社長向けご提案  
説明できる AI 社員 — for Grok Bot

---

# いま、社長が止まっている理由

- 現場は ChatGPT や AI を使いたい
- 「何を外に出したか分からない」で止めに入る
- **禁止すると、現場は隠れて使う**
- 決済や連携だけ先に付けると  
  「動くが、説明できない AI」になる

> 便利さは欲しい。でも事故の説明責任は社長にある。

---

# 見落としがちな事実：共有PC

Grok Bot の実行コンピュータは、御社の箱の中で**共有**されます。

| 分かれるもの | 共有されうるもの |
|--------------|------------------|
| 画面（デスクトップ） | ファイル・入れたツール |
| | ブラウザのログイン |

**OSだけでは「営業Bot」と「経理Bot」を切れません。**

Botを増やしても、手足は同じ箱。  
だから職務分離は、OSではなく**別の層**で張る必要があります。

---

# Staffpass とは

<span class="brand">Staffpass</span> は、Grok Bot の外側に載せる  
**AI社員の社員証・社長承認・仕事の記録**です。

| 層 | ひとことで |
|----|------------|
| **社員証** | 職務・目的・スコープ・期限。失効できる |
| **ゲート** | すべての実行は必ず通過。不一致は止める |
| **承認** | 危険操作は社長（または代理人）が許可してから |
| **監査** | 誰が・何目的で・何をしたか。後から説明できる |

> Grok Bot は優秀な手足。  
> Staffpass は、その手足に**社員証と承認印**を付ける製品です。

---

# 解決は4ステップ

1. **認める** — 手足の環境は共有。隠さない  
2. **雇う** — AIを「ソフト」ではなく **AI社員** として採用  
3. **境界を張る** — 社員証・承認・監査で職務を分ける  
4. **巻き取る** — 難しい接続は Managed。社長は承認と方針に集中

禁止するな。説明できるレールを敷け。

---

# デモで必ず見せる3点

1. **AI社員の権限**  
   「この子はここまで」が一目で分かる

2. **承認待ちで止まる**  
   社長がボタンを押すまで、危ない手は進まない

3. **監査タイムライン**  
   あとから「誰が・何のために・何をしたか」を追える

NGデモ：自動で何でも買ってしまう見せ方（不安が増えるだけ）

# Before / After

| よくある不安 | Bot だけ | **+ Staffpass** |
|--------------|----------|-----------------|
| 誰の手か分からない | 共有環境のまま | AI社員ごとに権限とログ |
| 勝手に外部送信・課金 | 止めにくい | 承認ゲート・fail-closed |
| 事故の説明 | チャット履歴頼み | 構造化監査・コストボード |
| セットアップ | 全部御社任せ | Managed で巻き取り可 |
| 紐づけ消失 | 不安 | 永続バインディング＋要再連携 |

同じ箱でも、営業Botと経理Botで**できること・ログ・承認**が違う。

# よくある質問（短縮）

**Q. データは学習に使われる？**  
A. Staffpass はプロンプト全文を溜めない設計。学習可否は Bot 側の契約事項です。

**Q. うちに情シスがいない**  
A. だから Managed。難しい接続はこちらでやります。

**Q. すでに ChatGPT を使っている**  
A. 併用でも、「公式の AI社員」だけでも始められます。

**Q. 共有PCのまま大丈夫？**  
A. 危険なのは共有より「境界がないこと」。境界を Staffpass に移します。
